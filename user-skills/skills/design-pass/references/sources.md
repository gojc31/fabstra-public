# Sources

Nine sources, in two kinds. Five steer the design and are reference-only: read for their rules and vocabulary, never run as their own flow. Three of those - frontend-design, Hallmark and impeccable - are skills installed on this machine at the paths given; Inspo is an MCP server; Emil Kowalski's skills are read only through impeccable's motion-craft.md. The other four kinds supply component code a builder takes in at step 5(c), by the stack and pass rules in [components.md](components.md); every one of their items is indexed by role in `D:\jc-ui-kit\CATALOG.md` (the default view, `core` and `standard` rows) or `D:\jc-ui-kit\CATALOG-archive.md` (`archive` rows) - look the role up in CATALOG.md first, then open the source's own file below for its rules: Bencho (bencho.dev, a public repo), JC's UI kit (`D:\jc-ui-kit`), ReUI (reui.io, through the shadcn registry) and the component libraries - affectUI first (free + Pro, no dependencies; affectUI Pro is recorded as owned and no other paid tier is; affectUI (free + Pro) is the first-ranked core source for every surface, app UI and landing alike; Pro code lives only in the project that uses it, never in this kit or a skill folder; rules in [affectui.md](affectui.md)), then free Pin UI (plain per-component CSS), Arc (CSS Modules), BoardUI and TailGrids, plus transitions.dev motion recipes; the other libraries JC collected are reference-only ([libraries.md](libraries.md)). Astryx, Meta's design system, is a whole stack rather than a per-component source: a project on it, or a new data or workflow app that adopts it, takes [components.md](components.md) section 10. Lenso UI is its own stack too: a project on `@lenso/ui`, or a new React 19.2+ app that adopts it, takes [components.md](components.md) section 11. All of them but transitions.dev are React, so on any other framework they are checklists only; transitions.dev's plain-CSS recipes and JC's kit lib files with no React import come across on every stack (components.md section 5).

**frontend-design** is Anthropic's plugin skill for distinctive visual direction - the base rule layer under step 5. This skill reads its "Process: plan, review against the brief, build, critique" section (the two passes, and the five saturated-default clusters used for the review), its "Design principles" section (typography, the hero, structural devices, motion), and its "More on writing in design" section (active voice, one name per action through a flow, errors and empty states). Its build step and its self-critique loop are not run from here. Path: `skills\frontend-design\SKILL.md` inside the `installPath` recorded for `frontend-design@claude-plugins-official` in `C:\Users\<you>\.claude\plugins\installed_plugins.json`; the version folder in that path changes on every plugin update.

**Hallmark** is the anti-AI-slop page-design skill - 21 macrostructures, 21 themes, and a 58-gate slop test - vendored from github.com/Nutlope/hallmark at commit 13ac0ec7e148 under MIT (Together AI). This skill reads four files for reference: `references/macrostructures.md` for the named page shapes step 5 picks from, `references/structure.md` for the six structural axes and the structural-variety rule, `references/anti-patterns.md` for the named tells, and `references/slop-test.md` for the gate numbers cited in `gates.md`. It also reads SKILL.md's component-scope signals. This skill NEVER runs Hallmark's Design flow, its three-question design-context gate, or its build step; Hallmark's own verbs are reached only through step 1's table. Path: `{{SKILLS_DIR}}\hallmark\`.

**impeccable** is the frontend design-and-refinement skill whose Commands table owns every terminal verb on an existing surface. This skill reads section 1 of `reference/new-work.md`, "Decide what is already true" (redesign, established world, incomplete brand, no visual authority - the INHERIT/OPEN call in step 3), and `reference/craft-floor.md` (the Verify list and the Refuse list, which supply the [IMP] gates). Section 3's concept-seed tournament and the DESIGN.md write at finish are impeccable's own flow, not this skill's: step 7 here writes its own, smaller record. Path: `{{SKILLS_DIR}}\impeccable\`.

**Inspo** is the MCP evidence source - a curated archive of production sites with real fonts, frequency-ranked palettes, named macrostructures, and desktop plus mobile screenshot pairs. This skill uses five of its tools and only in step 4: `get_filters()` for valid enum values, `recommend(brief, macrostructure?, pageType?, mode?, vibe?, color?, device?)` where `mode` is the light/dark axis, `search_screens(query, ...)` with `detail: "concise"`, `get_screen(slug)`, and never `get_design_system(slug, live?)` with its default `live: true`. List tools take `maxTokens`; the cap is approximate, and the top result and all URLs always survive it. The lite profile exposes nine tools, the full profile fifteen. Hosted endpoint: `https://inspomcp.dev/api/mcp`; docs: `gh api repos/Nutlope/inspo/contents/apps/mcp/README.md --jq .content | base64 -d`.

**Emil Kowalski's skills** (github.com/emilkowalski/skills, commit 2d22863, 2026-10-11, MIT) are the motion and interaction-feel source, read only through their distillation at `{{SKILLS_DIR}}\impeccable\reference\motion-craft.md`: its Never ship table backs step 1's motion-review row and its hard rules back the [EMIL] gates; the upstream skills are not installed.

**Bencho** (bencho.dev) is one of the component sources step 5(c) weighs, as code on a React stack (plain CSS, or Tailwind with its tokens mapped); on any other framework it is an interaction reference only. Unlike the sources above it supplies code: the builder takes a free block's raw files from the public repo first - raw.githubusercontent.com/cabralorenzo/bencho/main/blocks/<slug>/ (TSX, CSS, README.md) plus tokens.css at the repo root - with the block page's "Copy prompt" (TSX + CSS + tokens) as the fallback, no sign-in either way, and adapts it to the Design block's tokens and Gates. Free blocks are MIT - licence https://bencho.dev/licence, checked 2026-10-18 - so the MIT header stays and a SOURCE.md records the URL and date; Pro blocks are paid and not catalogued because Bencho Pro is not owned. The catalogue (block names, URLs, free/pro, fit tags, the adaptation checklist, best picks) is [bencho.md](bencho.md).

**JC's UI kit** (`D:\jc-ui-kit`) is one of the component sources step 5(c) weighs: code on a React plain-CSS stack, and a behaviour reference on React + Tailwind and on any other framework. A greenfield project takes the full root setup; an INHERIT or EXISTING pass takes the integration variant in [components.md](components.md), which never imports `styles\base.css` and keeps the incumbent's global styles. It supplies code built from JC's own code (the two 2026-10-18 run-monitor trial builds), reviewed and browser-verified, and production-ready - real data arrives through props, unlike Bencho's demo blocks. Stack: React 18 or 19, TypeScript, plain CSS that reads only the `--kit-*` tokens in `tokens\tokens.css`, framer-motion, lucide-react; nothing is on npm. Copy-in components (29 on 2026-10-25; CATALOG.md and the kit README list them) plus `lib\` and `styles\base.css`. A project copies a component's folder and everything its README's "Copy these" list names, following the root README's "Copy a component into a project" steps (shared files once, `initModality()`, the `<Toaster />` and `<TooltipLayer />` mounts). Each component README's Motion and Keyboard sections are its behaviour contract; the kit's motion rules follow motion-craft.md and gates 31-31d. Index, token contract and motion summary: `D:\jc-ui-kit\README.md`.

**ReUI** (reui.io, github.com/keenthemes/reui, by Keenthemes) is one of the component sources step 5(c) weighs for complex widgets and form controls on a React + shadcn stack (React + Tailwind through `shadcn init`, components.md section 3), and the feature checklist for a fresh build anywhere it cannot install: plain CSS, React + Tailwind on an INHERIT pass without approval for shadcn, any other framework. It is a shadcn/ui library - React 18+, TypeScript, Tailwind CSS, a Radix UI and a Base UI flavour of each in-house component - whose free tier (27 in-house components, among them a TanStack Table data grid, plus 1,264 composed examples) is MIT, checked 2026-10-19; Pro (from USD 249, one-time) is not catalogued because it is not owned (licence reui.io/legal/license, last updated 2026-09-28, checked 2026-10-19). Code arrives through the shadcn registry: `npx shadcn@latest add @reui/<slug>`. Its motion is not known to follow motion-craft.md, so an adapted component passes gates 31-31d; in a plain-CSS project its Tailwind classes are baked in, so it is never imported there. Its free MCP server is JC's to add if he wants it. The catalogue (components by fit tag, data-grid features, install, adaptation checklist) is [reui.md](reui.md).
