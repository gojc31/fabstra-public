Verify by running: a change is done once it has run, not only passed unit tests - the project's `verify` or `run-<name>` skill, the app, or the changed command - and your report says what you observed. The checks that judge a change (its tests, REVIEW.md, lint, CI and hook config) change only when the task names them. A flaky test gets its root cause; retrying, sleeping or skipping until it passes hides the failure, so report it instead. Three failed rounds on the same check: stop and report the evidence instead of trying again.
